# 시연 준비와 수동 점검

이 문서는 계획서의 시연 데이터·통합 시나리오 준비를 위한 입력 예시입니다. 계정이나 모임은 자동 생성되지 않습니다. 실제 개인정보 대신 아래와 같은 시연용 값을 사용하세요.

## 계정과 날짜

| 역할 | 이메일 예시 | 이름 예시 |
|---|---|---|
| 팀장 | leader@demo.test | 시연 팀장 |
| 참여자 | member@demo.test | 시연 팀원 |
| 미응답 확인용 | waiting@demo.test | 대기 팀원 |
| 비참여자 | outsider@demo.test | 외부 회원 |

비밀번호는 각자 정한 시연용 비밀번호를 사용합니다. 날짜는 실행하는 날의 내일·모레를 골라 과거 날짜가 되지 않게 하세요. 일반 창과 시크릿 창 또는 서로 다른 브라우저를 사용합니다. 같은 브라우저의 일반 탭끼리는 로그인 세션을 공유합니다.

## 두 계정 정상 흐름

1. 팀장이 ‘백엔드 발표 준비’ 모임을 만들고 내일·모레를 후보 날짜로 지정합니다.
2. 참여자가 초대 코드로 들어갑니다. 팀장과 참여자가 모두 목록에 있는지 확인합니다.
3. 팀장은 내일 15시·16시, 모레 14시를 저장합니다.
4. 참여자는 내일 15시, 모레 14시를 저장합니다.
5. 각 계정으로 다시 상세를 열어 선택이 복원되는지 확인합니다.
6. 조율 화면에서 내일 15시와 모레 14시만 공통 시간인지 확인합니다.
7. 장소 후보 ‘학교 도서관 스터디룸’과 ‘학교 앞 카페’를 등록합니다.
8. 각자 다른 장소에 투표한 뒤 참여자가 팀장과 같은 장소로 표를 바꿉니다. 이전 장소 -1표, 새 장소 +1표, 총 2표인지 확인합니다.
9. 참여자는 확정할 수 없고 팀장은 최다 득표 장소와 공통 시간을 선택할 수 있는지 확인합니다.
10. 팀장이 확정한 뒤 두 계정에서 날짜·시작·종료 시각·장소를 확인합니다.
11. 확정 후 시간 변경, 장소 추가, 투표가 닫히고 새 초대 참여도 거부되는지 확인합니다.
12. 서버 재시작 후 결과가 유지되는지 발표 PC에서 확인합니다.

## 별도 모임으로 확인할 오류 사례

확정 후에는 취소·재확정을 지원하지 않으므로 사례마다 새 모임을 사용하세요.

| 사례 | 준비 | 기대 결과 |
|---|---|---|
| 미응답 | 대기 팀원이 참여하고 시간 응답을 하지 않음 | 미응답자 표시, 확정 차단 |
| 가능 시간 없음 | 참여자가 별도 ‘가능 시간 없음’ 버튼 선택 | 미응답과 구분, 전원 공통 시간 없음 |
| 공통 시간 없음 | 팀장 내일 15시, 참여자 내일 16시만 저장 | 공통 시간 없음 표시, 확정 차단 |
| 최다 득표 동률 | 두 회원이 서로 다른 후보에 한 표씩 투표 | 팀장이 동률 후보 중 선택 가능 |
| 비참여자 접근 | 외부 회원이 다른 모임 주소로 접근 | 모임·조율·결과 접근 차단 |
| 중복 참여 | 같은 초대 코드로 다시 참여 | 중복 참여 안내, 인원 중복 없음 |

## 제출 전 직접 완료 표시

- [ ] A PC에서 IntelliJ·DB 연결·기본 검사가 성공했다.
- [ ] B PC에서 같은 ZIP으로 실행했다.
- [ ] 두 계정 정상 흐름과 위 오류 사례를 직접 확인했다.
- [ ] 발표 PC에 시연 계정·날짜·모임을 준비했다.
- [ ] 발표 자료에 역할 분담·ERD·권한·잠금·검사 결과를 넣었다.
- [ ] 두 사람이 대본을 정하고 전체 시연을 리허설했다.
- [ ] 최종 ZIP에 실제 비밀번호·개인 DB·빌드 캐시가 없는지 확인했다.

위 체크박스는 두 사람의 실제 작업이므로 자동 검사 성공만으로 완료 표시하지 않았습니다.
