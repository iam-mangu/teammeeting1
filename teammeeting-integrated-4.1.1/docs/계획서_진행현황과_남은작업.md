# 계획서 진행 현황과 남은 작업

평가일: 2026-11-13. 기준은 합의한 3주 계획서와 대화에 명시된 공통 프롬프트입니다. 기술 버전은 사용자가 이후 확정한 Spring Boot 4.1.1, Java 17, Mustache, Lombok 기준을 따릅니다.

## 1. 받은 B 코드의 진행 범위

작업일은 실제 걸린 날짜가 아니라 계획서의 작업 단계를 뜻합니다. ZIP만으로 B가 실제로 며칠 일했는지는 알 수 없습니다.

| B 담당 항목 | 계획서 단계 | 받은 ZIP에서 확인한 상태 |
|---|---|---|
| 공통 엔티티·로그인 계약 사용 | 1~2일차 | 공통 뼈대 기반. A의 최신 로그인·화면 설정을 유지해 연결 가능 |
| 장소 이름·메모 등록, 후보 목록 | 3~5일차 | Controller·Service·DTO·화면 포함 |
| 전체 참여자 기준 공통 시간 계산 | 초안 3~5일차, 본 구현 6~8일차 | 구현 포함. 미응답자 표시, 전원 교집합, 날짜·시간 정렬 |
| 1인 1표·다른 후보로 표 변경 | 6~11일차 | 구현 포함. 같은 표 행 수정, 다른 모임 후보 거부 |
| 팀장 확정·최다 득표·동률 선택 | 9~11일차 | 구현 포함. 전원 응답·공통 시간·최소 1표 조건 검사 |
| 날짜·시작·종료·장소 저장, 결과 화면 | 9~11일차 | 구현 포함 |
| 참여자·팀장 권한, 확정 후 변경 차단 | 12~13일차 검증 대상 | 서버 보호 로직과 규칙 테스트 포함 |
| 동시 투표·동시 확정 검사 | 12~13일차 | 받은 ZIP에는 없음. B_수정내역.md와 테스트 주석에도 추후 작업으로 명시 |
| A 연결 후 전체 화면 흐름 검사 | 통합·12~13일차 | 받은 ZIP에서는 미완료라고 명시 |
| 발표 자료·리허설·제출 환경 확인 | 14~18일차 | 받은 ZIP으로 완료 확인 불가 |

결론: B는 계획서의 9~11일차까지에 해당하는 주요 업무 기능을 구현했고, 12~13일차 검증 대상의 보호 로직도 작성했습니다. B 파트의 기능이 최종까지 존재한다는 뜻이며, 3주 계획서 전체를 끝냈다는 뜻은 아닙니다.

B ZIP에는 CoordinationServiceTest의 규칙 검사 9개가 있습니다. 다만 docs/검증결과.md는 이전 공통 뼈대 7개 검사에 관한 기록이므로, 그 문서만으로 최신 B 업무 검사를 모두 실행했다고 판단하지 않았습니다. 현재 통합본에서는 B 검사도 함께 실행했습니다.

## 2. 그에 맞춰 연결한 A 담당 범위

| A 담당 | 통합 상태 |
|---|---|
| 버전·의존성·공통 엔티티 7개·공통 저장소 5개·잠금 기준 | 기존 A 4.1.1 기준 유지 |
| 회원가입·로그인·로그아웃·이메일 중복 방지·비밀번호 해시·CSRF | 연결 완료 |
| 내 모임 목록·모임 생성·초대 코드 참여 | 연결 완료 |
| 생성자 자동 참여·중복 참여 방지·모임 접근 권한 | 연결 완료 |
| 후보 날짜 최대 7개·중복 및 과거 날짜 검증 | 연결 완료 |
| 09~20시 시작 12개 시간 슬롯·저장·수정·복원 | 연결 완료 |
| 미응답과 가능 시간 없음 구분 | 연결 완료 |
| A 상세 → B 조율 → 결과 및 돌아가기 링크 | 연결 완료 |
| 확정 후 신규 참여·시간 수정 차단 | B 확정 처리와 함께 검증 완료 |
| 실행 안내·시연 입력 예시·통합 검사 결과 | 이 통합본에 문서 포함 |

이전에 만든 A 담당 완료본을 사용했고, B 업무 기능을 새로 작성하거나 별도 가짜 구현으로 대체하지 않았습니다.

## 3. 통합본에서 완료한 필수 검증

기존 공통 7개 + A 14개 + 받은 B 규칙 9개 + 통합 흐름·경합 12개 = 총 42개입니다. H2 및 별도 MySQL 8.0.45에서 각각 실패 0개·오류 0개를 확인했습니다.

- 실제 회원가입·세션 로그인 두 계정 → 생성·초대 참여 → 시간 저장 → 장소 등록·투표 → 팀장 확정 → 양쪽 결과 조회
- 비참여자 접근, CSRF 없는 변경 요청, 일반 참여자의 확정 요청 차단
- 미응답·가능 시간 없음·공통 시간 없음 및 날짜별 공통 시간 정렬
- 표 변경, 반복 투표, 최다 득표와 동률 선택
- 확정 후 A·B 변경 요청 모두 차단
- 같은 계정의 동시 투표에서도 1인 1표 유지
- 동시에 확정 6회 요청 시 1회만 성공
- 참여·시간 수정·표 변경·장소 등록과 확정 사이의 경합 검사

동시 요청 검사는 한 서버와 해당 모임 행 잠금을 사용하는 최소 구현 기준입니다. 외부 서버 배포나 대규모 부하 검사를 했다는 뜻은 아닙니다.

## 4. 계획서의 최종 제출까지 남은 일

확인한 필수 기능과 검사 범위에서 새로 추가해야 할 주요 업무 기능은 발견하지 못했습니다. 다음은 기능 추가가 아니라 계획서의 마무리 작업입니다.

| 남은 일 | 담당 | 완료 기준 |
|---|---|---|
| 각자 IntelliJ·Java·MySQL 설정으로 실행 | A·B | 본인 PC에서 로그인·모임·시간·투표·확정까지 실행 성공 |
| 실제 브라우저 두 계정 수동 시연 | A·B | 정상 흐름, 미응답, 공통 시간 없음, 투표 변경·동률 사례를 직접 확인 |
| 공통 시연 데이터 준비 | A 중심, B 확인 | 시연_준비와_수동점검.md의 예시를 발표 PC에 입력하고 재접속 후 복원 확인 |
| 발표 자료 작성 | A·B | 목적, 역할 분담, 화면 흐름, ERD, 권한·트랜잭션·잠금, 주요 검사 결과 설명 |
| 발표 대본·리허설 | A·B | 두 사람이 각자 맡은 코드를 설명하고 전체 흐름을 끊김 없이 시연 |
| 같은 통합본 공유 및 최종 ZIP 확인 | A·B | 동일한 소스를 사용하고 비밀번호·개인 DB·빌드 캐시 없이 제출 |
| 리허설에서 발견한 오류 수정 | 관련 담당 | 수정한 내용 재검사 후 제출본 확정 |

각자 PC와 발표 장소에서의 실행은 아직 대신 확인하지 않았습니다. 발표 슬라이드·대본과 두 사람의 리허설도 이 ZIP에 완료본으로 들어 있지 않습니다. 따라서 필수 기능 구현·개발 환경 검사는 끝났지만, 계획서 14~18일차의 제출 준비까지 전부 완료한 상태라고 표현하지 않습니다.

## 5. 이번에 추가하지 않은 것

파티룸 예약, 위치 중심 찾기, 이동시간 추천, 지도·AI·외부 API, 채팅·알림, 재확정, 참여 인원순 추천 등은 추가하지 않았습니다. 이전 아이디어는 별도 후보일 뿐입니다. 사용자 지시대로 현재는 계획서 필수 범위만 유지합니다.
